# P2〜P8 実装・公開候補の記録

ユーザーの「計画書に従い実装開始」「ページ公開まで作業実施（ランキング連携は対応しない）」に基づく継続実装。基点はP0/P1採用済みmain `df519da`。README、固定要件、計画書の本文を保持する。

## 実装

- P2: 固定Kaisenの通常飛行、姿勢、宙返り、カメラ、照準を数値アダプタで移植。海空のshaderと航空機モデルを継承。閉じた16角の独自浮遊島、全方向sweep、境界、固定出撃点、翼戦士の自由飛行、艦の環状航路を接続。
- P3/P4: 機銃/機関砲、弾倉・装填、発射時帰属、全体発射予算、公平攻撃枠、島/海/実体の最初の連続衝突、火傷の独立区間積分、次tickから300tickの氷。
- P5: 全死亡を一括確定し敗北優先の終端へ接続。実HP減少だけを得点台帳へ記録し、一度だけfreezeした結果スナップショットを表示。
- P6: Home/HUD/Pause/Result、native設定/ルールdialog、9キー、Normal4/Easy1、3専用保存キー、失敗復元/今回だけ適用、物理解放ゲート、PauseのTab境界。
- P7: 固定海空/機体と独自島/翼戦士/味方艦隊、有限描画pool、火氷の形と状態ラベル、画面外案内、音初期OFF・同時上限・終了/再出撃の解放。
- P8: 純粋状態、数値移植回帰、描画cadenceの決定性、自然な無操作終端、強制容量不足、再出撃、ブラウザ画面と入力、固定参照比較を検査。

状態の正本は描画から独立した`simulation.ts`。3D/HUD/音はその結果を読む。開発用の結果fixture/観測APIはproduction buildから除去する。ランキング、名前入力、得点送信、爆弾/魚雷、元作の増援回復や得点式を実装していない。

出典台帳は`docs/evidence/*-adaptations.json`、戦闘の検査/出典は`combat-acceptance.json`。初回のsource取得台帳はP0/P1時点の記録として保持し、今回の移植完了範囲とは区別する。

## 検査の扱い

各検査の最終コマンド・候補SHA・成功件数は最終PR本文へ記録する。下記の観測値は検査担当の詳細証拠と併記し、未確認項目を合格にしない。

- 固定元との通常飛行数値比較の最大差4.55e-13、カメラ24姿勢の最大差8.24e-13。数値の一致は実描画の外観一致と分ける。
- seed20261005/Easy/無入力の30/60/120fps再生は同じ全状態hashで、26,684tick（444.733秒）に敵100撃破で勝利。得点3,400、損失自機0/僚機13/艦4。初期無操作の自機実損傷0なので時間加点0。
- 同runの最大航空弾96/魔法弾193/対空弾6、火傷24、tickイベント14。通常容量の発射保留0。強制0容量は別検査で非消費・次tick再試行を検査。
- 上の自然runは10分より前に終端するため「10分active連続」合格とはしない。別の兵装停止fixtureで8/24/10を36,000tick維持し、10分の運動/状態構造の有界性を検査する。自然な10分戦闘やGPU性能の代用ではない。
- 初回GPU backend準備は固定版と同じく作戦開始前に上限付きで待つ。実GPU fence完了前はStart無効。稼働中の1秒GPU stalled検出と最大8tickの処理予算は維持する。

## ソフトウェア描画で観測した制約

Linux/Chromium 149/SwiftShader、393×852では再出撃中にGPU fenceが1,007〜1,084ms pendingとなり、製品の1秒停止判定で明示的に停止した。計画の393×648ではDOM射撃・停止・説明・再開・5回再出撃の検査が成功した。この差を実機性能の合格とは扱わず、GPU停止判定を緩和しない。

## 未確認事項

iPhone実機Safari・実機モバイルGPUの通常60秒/最大120秒/連続10分の性能は未確認。Linux/Chromium/SwiftShaderでの画面・資源確認を実機合格としない。実機測定の代わりに戦力・火力・判定を変更しない。

ブラウザのResult画像は明示した純粋simulationの損傷fixtureから製品の終端/得点経路を通し、画面へ注入して撮影する。実際のDOM操縦経路と区別し、DOM入力で敵100人を撃破した証拠とは扱わない。
