### 2.2 固定版との画面比較を受入にする

実装時は上記Kaisen/FFの固定SHAを、それぞれの隔離した参照用コピーとして同じブラウザ・OS・DPR・viewportで起動する。各作品のmainや公開URLの現配信を固定版の代わりにしない。参照元リポジトリへ変更を書き戻さない。

比較セットは393×648、568×320、1280×720ごとに、Home、Normal HUD、Easy HUD、Pause、タッチ設定、PCキー設定、ルール、Resultを揃える。同じ入力方式、モード、設定値、スクロール位置、フォーカス位置、音状態で撮影し、基準SHA/候補SHA/画面状態を画像に対応づける。動く世界と表示数値を無制限に隠さず、本作固有差分だけを比較除外リストへ明記する。

機体とカメラは別に、同じ機体姿勢・速度・高度・光・カメラ条件の比較画像を用意する。機首、翼、風防、舵、プロペラ、画面内の大きさ/位置、FOV、照準の重なりを確認する。新作の島があるという理由で航空機モデルやカメラの比較を省かない。

既存のスクリーンショット検査と目視を使い、DOM矩形、CSS値、実表示の一致を確認する。アンチエイリアス等の差は記録して区別し、差分画像の面積しきい値だけで合格にしない。共通UI/機体/カメラに説明のない外観差があれば未完了として修正する。これはA07/A15〜A18の受入に含める。参照コピーを起動できない場合は比較未実施として報告し、「シリーズUI統一済み」としない。

## 3 論理データと不変条件

各工程の完了条件にある受入IDは、その工程が担当する観点を指す。1つの受入IDが複数工程にまたがる場合、未実装の依存機能まで合格扱いにしない。例としてA05の航行はP2、対空はP3、氷はP4、A13の発射時帰属はP3、得点確定はP5で検査する。受入ID全体の最終合否は必要工程の完成後にP8で確定する。

### P1 作戦状態と有限戦力

依存: P0。

描画ライブラリから独立した作戦状態に次を持つ。

- missionId、rulesVersion、seed、tick、phase（loading/home/playing/paused/result）、finalized
- 味方A001〜A050の排他状態、枠、予約期限、HP、role、基準速度、装填、効果
- 敵E001〜E100の排他状態、予約期限、HP、実速度ベクトル、弾倉、攻撃枠所有
- 艦S001〜S010の生死、HP、航路、基準/実速度、装填、対空枠所有
- controlledAircraftId、各陣営の発射予算、発射ID単調カウンター、有限論理弾pool
- 実損傷/撃破/損失/時間の得点台帳、結果スナップショット

各tick終了に `Areserve+Apending+Aactive+Alost=50`、`Ereserve+Epending+Eactive+Edefeated=100`、`Salive+Ssunk=10` を検査可能にする。active＋pendingの8/24枠、controlled IDの一意性、HP範囲、lost/defeatedから戻れないことも同じ状態管理で守る。

初期化を一つの経路にまとめる。再出撃はmissionIdを更新し、UI callback、入力、弾、火傷、装填、予約、音を古い作戦へ結び付けて無効化する。画面演出やtimeoutから予備を直接増減しない。IDを描画poolの再利用番号と兼用しない。

自機死亡の全tick処理後に、未予約reserve→既存pendingの付替え→最小ID生存僚機の順で操縦対象を確保する。候補死亡・pending完了・同時死亡のたびに再評価する。予約付替えは1トランザクションで、期限や残機を増やさない。生存僚機引継ぎはHP/弾倉/装填/火傷/氷を維持し、入力保持・旧カメラ補間・宙返り途中状態をリセットする。次の入力はキーや指を一度解放してから受理する。

完了条件: A01〜A04の純粋状態ケースで保存則・復帰・引継ぎが成立し、敵0activeを勝利と誤認せず、正の残機で操縦権確保が永久待ちにならない。まだ3D画面の完成を要求しない。

### P2 地形と運動

依存: P1。独自素材の権利確認は並行可能。

1. 島の水平最大半径1,000m、上面800m/下端300mの閉じた簡易collision形状と、外周8出撃口、味方8待機点を先に定義する。見た目の詳細から衝突仕様を逆算しない
2. 島全体の広域境界と、近傍の閉じた低解像度mesh/複数凸形状を接続する。前位置→次位置のsweepで最初の接触時刻を返す。上面、側面、下面、稜線、裏面、極短線分、初期重なりを扱う
3. 戦場6km/高度2.5kmの境界と警告を実装し、外向き速度成分だけを抑える。内向き操作、通常旋回、カメラを保持する
4. Kaisenの航空機飛行を基準速度vBaseと実移動速度のアダプタで接続する。通常時の姿勢・速度・宙返りは固定元と比較し、氷の追加で通常挙動を変えない
5. 敵の自由飛行を航空機のcontrollerと分ける。2.777…〜16.666…m/s、加速度8m/s²、旋回120度/秒を守り、島回避と離脱/再接近を作る。胴体球半径2.5m、外観4m/翼8mを対応づける
6. 艦の2〜3km環状航路と位相、6m/s、氷停止、後続減速、沈没除外を接続する

完了条件: A05〜A07。全方向の島遮蔽、島上下衝突、安全出撃、境界内向き操作、敵の速度範囲を検証する。島の描画LODを変えても衝突結果を変えない。敵速度に戦闘機失速下限を適用していない。

## 4 戦闘と状態異常

### P3 兵装と発射予算

依存: P1/P2。

自機/僚機の機銃288・機関砲96、空の両弾倉を6秒で補給する。射撃周期、基礎威力、4段階距離減衰、1.5秒寿命を固定要件と照合する。弾には発射ID、missionId、ownerId、sourceRoleAtFire、発射位置/方向、実飛翔距離、寿命を保持する。発射後の操縦引継ぎ・owner死亡は帰属を変えない。

論理弾の確保、弾倉減算、発射時計更新を原子的に行う。2発同時の必要枠を確保できなければ両方を保留し、次tickに再試行する。描画tracer不足では論理弾を消さない。僚機装填は元作との差として明示し、引継ぎ後の発射時計を勝手に0へ戻さない。

敵は入場・生存・射程・遮蔽・装填を満たす場合のみ攻撃枠を取る。8枠、対象ごと2、2秒ごとの公平交代、15tickごと全体8発（未使用失効）を独立管理する。敵ごとの4発/秒、12発/3秒装填、火氷交互も同時に守る。対象喪失・死亡・装填で枠解放、飛行中の弾は維持する。艦側は4枠、60tickごと全体4発、各艦1発/秒・6発/4秒装填とする。

連続衝突は島/海/有効実体の最初の接触だけ。魔法弾は200m/s・6秒、対空弾300m/s・3秒、発射後に曲がらない。味方兵装は敵のみを損傷し、敵弾は味方機/艦のみを損傷する。

完了条件: A08/A09/A13。空弾倉、片方のみ空、停止、pool不足、枠交代で弾消費・発射回数が増減しない。敵の全3種の対象選択と公平性を検査する。

### P4 火傷と氷

依存: P3。

火傷は命中ごとの別レコードであり、単一の「燃焼中タイマー」へ潰さない。開始t、終了t+1秒、8HP/秒、projectileId、targetIdを持ち、積分区間の共通部分だけ損傷する。衝突イベントを時刻順に処理する際、直前イベント時刻から現在時刻まで既存火傷を進め、新規火傷は残区間だけ積分する。死亡に達した時刻以降は同対象の実損傷を0とし、死亡確定イベントは1件にする。発射者死亡で状態を削除しない。

氷は命中tick+1の開始tickを適用境界として保持し、300tickの期限を持つ。再命中はその次tickから300tick後まで期限を更新し、量も時間も加算しない。移動済みtickを巻き戻さない。次tickの移動前に適用/満了を処理し、基準速度から50/3.6m/sを一回引く。航空機最低65m/s、艦最低0。操縦targetSpeedを減らしてからさらに実速度を減らす二重処理を禁止する。

火傷512件の共有固定poolを用意する。飛行中256発＋1秒の最大40発という保守上限296件を収容する。対象ごとの参照も最大512件まで扱い、論理効果を画質で省略しない。新規出撃で効果を消す一方、生存機引継ぎでは残す。

完了条件: A10/A11。時間分割の違い、ずれた多重火傷、集中着弾、発射者死亡、対象死亡、停止、再出撃/引継ぎ、tick初期/末端の氷命中、300tick境界を検証する。火傷の整数tick丸めと、氷の秒/フレーム混同を起こさない。

### P5 終端と得点

依存: P1〜P4。

固定要件R14の順序を製品の一つのstep関数へ集約する。移動/発射はtick開始時生存を基準とし、当該tickの衝突・火傷を全処理してから死亡を一括確定する。時計、予備、枠、得点の更新を描画callbackへ分散させない。最後の敵と味方/艦が同tickで全滅したら敗北優先。結果確定後は不変スナップショットを表示し、遅延弾・効果・予約を無効化する。

得点は `100*K + 5*Dplayer + TimeBonus - 500*Lplayer - 200*Lwing - 1000*Lship` とし、正本R16をそのまま使う。損傷台帳は敵IDと一意イベントIDに結び付ける。実HP減少だけを加算し、1敵80/全体8,000を超えない。発射時に自機だった弾は、発射者死亡後の着弾でも自機貢献。操縦されていなかった味方の古い弾を引継ぎ後に自機貢献へ変えない。

敵の地形事故もKへ入るがDplayerには入らない。僚機・艦のとどめで自機の既得実損傷を消さない。自機と僚機の損失は死亡時の役割で排他計上する。時間点は勝利時1回だけ、600秒で0、Dplayer=0で0。Easy自動射撃が実損傷を与えた場合は貢献に含める。命中率項目を追加しない。

完了条件: A12〜A14。全終端組合せ、ID重複、overkill、旧自機弾、全自動味方のみの撃破、時間境界0/600/600超、丸め、得点範囲[-35,000,60,000]を検証する。結果表示前後や複数frameで点が変化しない。

論理弾poolの強制枯渇ケースでは非消費再試行が正しいことを確認する。一方、通常の上限構成で自然に枯渇する候補は性能合格にしない。意図した強制枯渇試験と製品での不足検出を区別する。

背景化・blur・context lossでは自動停止し、再開時の追いつきtickを実行しない。1frame8tickの処理予算を超え続けたら負荷停止する。作戦時間の切捨てや無限whileによるUI停止は不可。停止していた経過を得点時間へ入れない。

試遊では島への進入経路、敵の速度差、攻撃回避、島裏の敵への接近、艦防衛、最後の予備、引継ぎ直後の把握をEasy/Normalで確認する。数値テストだけで「面白い」「回避可能」「全端末で快適」と結論しない。無操作での勝敗も観測して記録するが、Easyの自動射撃を不正とみなさない。

性能未達はまず描画品質を調整する。論理人数・火力・速度・弾寿命を端末別に黙って減らさない。同時数やHP等[D]を変更する場合は理由とルール版を記録し、保存則、容量根拠、難易度、得点境界の影響を再検証する。iPhone実機が使えなければ「未確認」のまま提出し、模擬WebKitやSwiftShaderを代用合格にしない。
